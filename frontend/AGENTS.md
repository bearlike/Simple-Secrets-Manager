## Scope

This folder contains the SSM Admin Console (Vite + React).

## Commands

- Install deps: `npm install`
- Dev server: `npm run dev`
- Lint: `npm run lint`
- Production build: `npm run build`
- Preview build: `npm run preview`
- Type-check (does NOT run in build/lint — run it explicitly): `npx tsc --noEmit`

## Backend integration

- API base URL is controlled by `VITE_API_BASE_URL`.
- Default API base is `/api`.
- Auth header expected by backend: `Authorization: Bearer <token>`.
- The API error envelope is `{"message": ...}`; `errorToast.ts` reads `message` first,
  then `error` (matches the backend — see
  [`ssm_server/api/AGENTS.md`](../ssm_server/api/AGENTS.md)).

## KISS/DRY Reuse Policy (Frontend)

- Keep frontend implementation intentionally simple: prefer straightforward composition over new abstractions.
- DRY first: before adding code, check whether the same UI behavior already exists in `src/components` and reuse it.
- Reuse order is mandatory: existing local component -> existing shadcn primitive/pattern already in repo -> package component already installed -> new component as last resort.
- If a feature can be built by composing existing shadcn components (`Dialog`, `DropdownMenu`, `Tabs`, `Select`, `Button`, etc.), do that instead of creating a new custom primitive.
- Avoid frontend sprawl: do not add new reusable components unless the same pattern is needed in multiple places or materially improves maintainability.
- When a new component is unavoidable, keep API and internal logic minimal, colocate it near usage, and avoid speculative/generalized props.
- Prefer extending existing components with `className`, small props, and composition rather than forking or duplicating markup.
- We are not a frontend-heavy project: optimize for low ownership and low maintenance by maximizing out-of-the-box component reuse.

### Planning/Research order for new UI work (do this first)

1. Check official shadcn docs + registry for a native primitive/pattern that matches the need (`ui.shadcn.com` docs + registry JSON).
2. Check `src/components/ui` for that primitive already present before adding anything.
3. If missing, add the official shadcn registry primitive (and only required companion deps/files) before designing custom UI.
4. Compose feature UI from those primitives first; only build a new custom component when composition is clearly insufficient.
5. Keep implementation minimal and local: small props, no speculative APIs, no duplicate wrappers around existing shadcn behavior.

## Session lessons (frontend)

- Forked config grouping can be implemented without backend contract changes by combining read-time calls:
  - child effective secrets (`include_parent=true`)
  - child direct secrets (`include_parent=false`)
  - parent effective secrets (`include_parent=true`)
- Fork diff display rule: if a child has a direct key with the same value as parent effective, classify it as `Inherited` in UI (no effective divergence).
- The official shadcn `Collapsible` primitive (`components/ui/collapsible.tsx`, on `@radix-ui/react-collapsible`) was intentionally introduced for the sidebar "Administration" group — new section toggles should use it rather than hand-rolling `Button` + chevron state.
- If parent comparison data cannot be loaded, degrade gracefully in UI (show a small note and keep table usable) instead of blocking the entire secrets view.
- Prefer the native shadcn `SidebarProvider` + `Sidebar` + `SidebarInset` + `SidebarTrigger` stack for app navigation; avoid custom `Dialog`-as-drawer rewiring because it tends to cause brittle styling and transparency regressions.
- For responsive top bars, keep only core actions always visible on small viewports (navigation trigger, breadcrumb context, account menu) and move secondary actions (export/settings/repo links/config switching) into a native shadcn `DropdownMenu` overflow.
- Keep theme mode controls out of crowded top bars on mobile-first layouts; place them in stable navigation surfaces (for example sidebar footer) to reduce header collisions and keep interaction targets accessible.
- For dense tables on compact widths, prioritize search/input width by switching secondary action buttons to icon-only with `Tooltip` labels and use the same row action definition to render desktop icon actions plus mobile `DropdownMenu` actions without duplicating behavior logic.
- Keep React Query derived views under a shared key prefix (for example `['secrets', projectSlug, configSlug, ...]`), and invalidate by that prefix (`['secrets', projectSlug]`, `['compare-secret', projectSlug]`) for project-wide mutations like icon recompute — one invalidation then refreshes every related view instead of each caller hand-listing keys.
- TanStack `queryFn` typing footgun: an API-client function used directly as `queryFn: fn` MUST stay parameter-less. React Query calls it with a `QueryFunctionContext`, so giving `fn` an optional-object param (`fn(opts?: {...})`) makes it a *weak type* the context cannot satisfy → `tsc` errors at every bare `queryFn: fn` call site and the query `data` degrades to `unknown`. `npm run build` (vite) and `npm run lint` (eslint) do NOT run `tsc`, so it regresses silently — run `npx tsc --noEmit` to catch it. For a filtered variant, add a sibling fn (e.g. `getArchivedProjects`) over a shared private helper instead of parameterizing the shared one (`src/lib/api/projects.ts`).
- Project archive UI reuses ONE `updateProject(slug, {name?, archived?})` (backend PATCH is a partial update) for BOTH the `ProjectCard` dropdown quick-action and the `EditProjectDialog` "Status" `Select` — no separate archive endpoint. The list filter is a shadcn `Select` (Active/Archived) mirroring `AuditPage`. Keep the default query key `queryKeys.projects()` === `['projects']` (archived view = `['projects','archived']`) so existing `invalidateQueries({ queryKey: queryKeys.projects() })` refreshes BOTH lists by prefix. `Sidebar` and other project dropdowns call the parameter-less `getProjects()`, so they stay active-only automatically.
- Secret sensitivity is server-driven and **default-sensitive**: `mapSecretsData` and `mapSecretComparisonRowDto` MUST default `sensitive` to `true` when the meta field is absent (raw exports / legacy docs carry no flag) — a `?? false` there would silently unmask every legacy secret. UI treats `sensitive === false` (not truthiness) as "render in the clear" and drops the reveal toggle for those rows. Provenance (`source`/`isInherited`) also rides in export meta and is only populated when the table fetch passes `includeProvenance: true`.
- For in-row hover hints (the "inherited from <config>" description and the last-updated absolute timestamp) prefer the native `title` attribute over the shadcn `Tooltip`, matching `CompareBySecretPage`'s `title={issue.message}`. Radix `TooltipTrigger asChild` needs a ref-forwarding child, and `Badge`/plain spans in table cells don't forward refs — `title` avoids that and keeps dense tables cheap.
- The `Switch` primitive (`components/ui/switch.tsx`, on `@radix-ui/react-switch`) was added for the EditSecretDialog "Sensitive" toggle; it's the official shadcn switch. Bind it with a react-hook-form `Controller` (`checked` + `onCheckedChange`), not `register`.
- **One relative/absolute time helper (`src/lib/time.ts`).** `SecretsTable`, `TokensTable`, and `ReloadStatusPage` each had their own `formatRelativeTime` (two near-identical manual minute/hour/day cascades plus one already-good `Intl.RelativeTimeFormat` version) and their own absolute-date wrapper (`toLocaleString`, `toLocaleDateString`, and a fixed UTC `YYYY-MM-DD HH:MM:SS` stamp respectively). Consolidated onto the `Intl`-based `formatRelativeTime` (better i18n/pluralization than manual `${n}m ago` cascades) plus a single `formatAbsolute(value, style)` with a `style` axis (`'datetime'` | `'date'` | `'timestamp'`) so the three genuinely-different absolute formats (locale datetime, locale date-only, fixed-UTC ops timestamp) stay available from one function instead of three copies. Placeholder text is standardized on `'—'` everywhere (was a `'-'`/`'—'` split before) — this is an intentionally allowed visual difference, unlike the badge-style consolidation below which must stay pixel-identical. One behavior worth preserving deliberately: `SecretsTable`'s absolute-time `title` attribute must stay `undefined` (not `'—'`) when there's no timestamp, so the native tooltip doesn't appear on rows with nothing to show — guard at the call site (`updatedAt ? formatAbsolute(updatedAt) : undefined`) rather than inside the shared helper.
- **Shared outcome badge axis (`lib/badgeStyles.ts`: `outcomeBadgeClass`/`outcomeAlertClass`/`outcomeTextClass`).** The green/red/yellow/blue bg+text+border Tailwind tuples were duplicated verbatim (byte-for-byte, verified) across `ReloadStatusPage` (two `Record` maps), `AuditPage`, `ImportEnvDialog`, `TokensPage`, and `CreateTokenDialog`. Consolidated behind a `success`/`error`/`warning`/`info`/`neutral` outcome axis, kept separate from the existing config-identity axis (`getConfigBadgeClass`, dev/staging/prod). Three accessors, not one, because the same color tokens get consumed in three different DOM shapes that must stay pixel-identical: `outcomeBadgeClass` (bg+text+border, for `Badge`), `outcomeAlertClass` (bg+border only, no text, for `Alert` containers whose `AlertDescription`/icon apply their own text color), `outcomeTextClass` (text only, for description text that happens to share the badge's shade). Two colors were deliberately left OUT of the axis: `ImportEnvDialog`'s "overwrite" action uses orange, and `ReloadStatusPage`'s "stale" badge uses amber — neither is duplicated anywhere else, so forcing them into the nearest semantic bucket (`warning`) would have changed the actual rendered color. Likewise `CreateTokenDialog`'s "shown once" alert icon (600/300) and description (800/200) use shades that don't match the badge's 700/300 text convention — real, deliberate emphasis choices, not duplication, so they stayed as local literals rather than being coerced into `outcomeTextClass`. Rule of thumb for the next duplicate-style hunt: only pull a color into a shared axis when the literal string matches somewhere else; a "close enough" semantic match that isn't a byte-identical duplicate is a visual regression risk, not a DRY win.
- **Zod at the API boundary (`lib/api/schemas.ts`), replacing hand-rolled `asString`/`asBoolean`/`asStringArray` guard chains in `mappers.ts`.** The schemas ARE the wire-shape documentation now — every field a DTO can carry, and exactly which legacy/alternate spelling is still tolerated, lives in one place instead of scattered `?? asString(dto.snake_case)` chains. Four `loose*` zod primitives (`looseString`/`looseBoolean`/`looseStringArray`, built on `z.unknown().transform(...)`) are the direct equivalents of the old guard functions: a field of the wrong runtime type degrades to `undefined`/`[]` instead of failing validation, so one malformed field never throws. `parseListSafely`/`parseRecordSafely` give the same fail-soft contract at the collection level (`z.safeParse` per element, skip failures) instead of `.map()` blowing up on one bad row. Snake_case fallbacks are NOT uniformly kept or dropped — the wire shape was verified per family before deciding: **projects list, configs create response, tokens list** genuinely dual-emit camelCase + snake_case (`created_at`/`expires_at`/`last_used_at`) from an in-flight backend migration, so those three schemas keep the snake field with an inline `// server dual-emits; snake fallback removable next major` comment; **comparison rows + secrets export meta** are pure camelCase already (their snake fallbacks were dead and got dropped, not ported); **audit events** stay heterogeneous by design (`.passthrough()` + known fields, replacing the old `AuditEventDto = Record<string, unknown>` escape hatch); **reload status** was already tolerant-mapped and got ported 1:1 (including its legacy alternate field names) rather than re-verified. Workspace/me DTOs weren't part of the verified audit, so their existing camelCase+snake fallbacks were ported unchanged rather than guessed at. One sharp edge: a generic helper like `parseListSafely<T>(schema: z.ZodType<T>, ...)` breaks with transforming (`ZodEffects`) schemas — `ZodType`'s third generic param (`Input`) defaults to `Output`, but a `.transform()` schema's real input is `unknown`, so TS rejects the object literal at the call site with a baffling `objectInputType is not assignable to objectOutputType` error. Fix: pin the input param explicitly — `z.ZodType<T, z.ZodTypeDef, unknown>`. Security-pinned fields (secrets `sensitive`, default-`true`-never-`false`) are deliberately kept as raw `z.unknown()` passthrough rather than routed through `looseBoolean`, so the mapper's exact `?? true` expression is untouched byte-for-byte — don't "clean up" a pinned-contract line just because a tolerant primitive is sitting right there.
- **Navigation consolidation: one canonical home per global control.** The TopBar is contextual-only (sidebar trigger, breadcrumb, config `Select`, project settings, export, plus their `lg:hidden` quick-actions overflow); everything identity/app-global lives in the sidebar. The sidebar footer's former 8 flat items collapsed into ONE `NavUser` control (`components/layout/NavUser.tsx`, canonical shadcn sidebar-user pattern: `SidebarMenuButton size="lg"` trigger with a plain-div initials avatar — deliberately no `@radix-ui/react-avatar` dep — opening a `DropdownMenu` with `side={isMobile ? 'bottom' : 'right'}`). It holds Account/Team/Groups, dark mode, the GitHub-version link, and Sign Out; Tokens/Audit Log/Reloader Fleet moved into an "Administration" collapsible `SidebarGroup`. Decisions to preserve: dark mode is a `DropdownMenuCheckboxItem` with `onSelect={(e) => e.preventDefault()}` so the menu stays open while toggling (announces state via `menuitemcheckbox`); `getMe`/`getAppVersion` queries live ONLY in NavUser now (they left TopBar with the controls) and `workspaceRole` from `/me` is finally rendered there; `REPOSITORY_URL` lives in NavUser (moved with its only consumer). The `DropdownMenuItem` primitive already styles bare child icons (`gap-2 [&>svg]:size-4`), so new menu items need no explicit icon size/margin classes — TopBar's remaining `mr-2 h-3.5 w-3.5` menu icons predate this and can be dropped opportunistically, not urgently. Verified with Playwright: menu keyboard nav + focus-return, theme persistence (`ssm_theme`), group collapse `aria-expanded`, mobile sheet auto-close on navigate.
- **The secret-icon picker (`components/secrets/IconSlugPicker.tsx`) is an Iconify-API-powered virtualized grid; cmdk was removed.** Data plane is the public Iconify API via `lib/api/iconify.ts` — `/search?query=&prefix=&limit=999` (ranked, alias-aware, cross-pack; `limit` clamps 32–999), `/collections` (all ~230 packs with display names + counts), `/collection?prefix=` (full pack contents; the client flattens `uncategorized` + `categories` into one list). This deliberately REPLACED the self-hosted `GET /api/icons/prefixes[/<prefix>/names]` catalog in the console: previews already hit `api.iconify.design` for every render, so online search/browse adds no new dependency in practice, while cross-pack search was impossible by construction on the pack-scoped endpoints. The backend endpoints stay live (published contract) but the console no longer calls them; offline the picker degrades to a status row while the free-text mono slug input — still the source of truth, still guarded by the zod `ICON_SLUG_PATTERN` refine — keeps working. `iconify.ts` colocates its zod fail-soft schemas (external service ≠ our API; `schemas.ts` stays our-API-only) and reuses the shared `looseString`/`looseStringArray`/`parseRecordSafely` primitives. Rendering is unchanged (`AppIcon` lazy-loads `@iconify/react`). **Why cmdk left**: it mounts every item (no virtualization), which is what forced the old picker's 50-row cap; this picker was its only consumer, so `components/ui/command.tsx` + the `cmdk` dep were deleted outright. The replacement grid uses `@tanstack/react-virtual` (row-virtualized, 8 tiles/row, `GRID_COLS` must stay in sync with the `w-[12.5%]` tile width) — the whole ~19.6k-icon `fluent` pack scrolls with only ~100 mounted DOM nodes (measured via Playwright). Keyboard nav uses the **aria-activedescendant highlight pattern, not roving focus**: DOM focus never leaves the search input, so virtualized tiles can unmount freely while scrolling; ArrowUp/Down move a row, Alt+Left/Right move a column (plain Left/Right keep editing the query text), Enter selects the highlighted tile. All three queries use `staleTime: Infinity` + `retry: 1` (snappy offline error) and search adds `placeholderData: keepPreviousData` to avoid grid flash between keystrokes; `getIconCollections` is passed bare as `queryFn`, the param-taking two are arrow-wrapped (the documented queryFn footgun above).
- **"Icon/sensitive edits don't save" was NEVER a frontend bug: the console's refetch was served a stale HTTP 304.** The save path (form → `iconSlug` → `icon_slug` → engine) and the query invalidation were verified correct end-to-end; the export ETag was value-only, so a metadata-only edit didn't flip it and the browser's conditional refetch re-rendered its cached pre-edit body. Fixed server-side (the meta representation's ETag now covers meta — see `ssm_server/api/resources/AGENTS.md`). LESSON for console debugging: when a mutation "doesn't stick" but the PUT returns 200, check the refetch's HTTP status FIRST — a 304 means the server said "unchanged" and no amount of React Query invalidation will help; invalidation triggers the refetch but cannot bust the HTTP-layer cache.
- **Per-secret `description` rides the same rails as `iconSlug`, and the table shows it WITHOUT a new column.** Wire: `description` in the PUT body (guarded `!== undefined` like `icon_slug`), `meta[key].description` on export (zod `looseString` in `secretMetaDtoSchema`, mapped in `mapSecretsData`). UI: a 2-row `Textarea` (primitive already existed) in Edit/Add dialogs; the table renders it as a `line-clamp-2` muted sub-line INSIDE the existing KEY cell. WHY no new column: `SecretsTable`'s empty/section/loading rows hardcode `colSpan={5}` and the skeleton hardcodes five `<TableCell>`s in several places — a 6th column silently breaks all of them; if you ever DO add a column, grep for `colSpan` and the caption text first.
- **`lib/snippets.ts` is a CONTRACT with the Python side, not just display text.** The config page's "Use this config" dialog (`components/configs/ConfigUsageDialog.tsx`) hands operators copy-paste-ready `ssm` / compose / `docker run` snippets, so every literal in that module has an authority it must track: the labels against `ssm_reload/config.py` (`ENABLE_LABEL`/`CONFIG_LABEL`/`REVISION_LABEL`/`KEYS_LABEL`), the projection dir + volume against the constants in the same file, the dotenv file name against `ssm_projection/sink.py::env_filename`, `SSM_RELOAD_PROJECTION_CONFIGS` against `ReloadSettings`, and the compose shape against the live-verified `ssm_reload/docker-compose.example.yml`. Drift here is worse than a typo: the operator gets a stack that *looks* wired up and silently never reloads. There is no JS test runner to catch it, so re-read the Python constants whenever you touch the snippets, and run the command you are about to ship against a real daemon. That is how the `docker run` snippet got fixed before it shipped: **`docker run --env-file` is not a dotenv parser** — it keeps quotes literally, so the quoted file `ssm secrets materialize` writes for compose injects `KEY="value"` *with the quotes in the value*. The unquoted `ssm secrets download --format env` is docker's dialect; compose's `env_file:` wants the quoted one. The two are not interchangeable — full rationale in [`ssm_projection/AGENTS.md`](../ssm_projection/AGENTS.md). Keep the module pure (project/config in, strings out) — the dialog is the only place React/`navigator` touch it.
- **The scope filters on `/reload` and `/audit` live in the URL, not in `useState`.** Both pages read `project`/`config` from `useSearchParams`, so `/reload?project=vpn&config=zurich` (and the same on `/audit`) is a deterministic, bookmarkable view — that is what lets `ConfigUsageDialog`'s footer deep-link into one config's fleet and its audit trail. Writes go through one `applyFilters`/`applyScope(project, config)` (with `{replace: true}`, so filter churn doesn't pile up in history) that enforces the invariant that a config slug is meaningless without its project — setting the project clears the config. Only the *identity* filters belong in the URL; genuinely ephemeral view state stays local (`AuditPage` keeps `since`/`page` in `useState`, and resets `page` inside `applyScope`). Don't reintroduce local state for the URL-backed filters: two sources of truth for one filter is how the URL silently stops matching the table.
- **One copy affordance: `components/common/CopyButton.tsx`.** It carries the copy-to-clipboard + transient "Copied" feedback that was inline in `CreateTokenDialog`. It also *catches* the clipboard rejection (the API rejects outside a secure context — a plain-http host, a denied permission) and toasts instead of leaving an unhandled promise rejection, which the old inline version did. Reuse it rather than re-hand-rolling the pattern.
- **The token-create "Access" preset is the ONLY source of a token's scopes from the console; a scope with no preset is unreachable.** `CreateTokenDialog` never sends a raw scope list — it sends `access: 'read' | 'read_write' | 'reload'`, and `mappers.ts::mapAccessToActions` is the single translation into the `actions` array the v2 endpoint persists (the backend stores whatever `actions` it's given; there is no server-side default or allowlist). So `reload:report` (needed by `ssm-reload`) was **unreachable from the UI** until a `reload` preset was added — every reloader token minted via the console silently shipped `[secrets:read, secrets:export]` and the reloader's fleet-report POSTs 403'd with `Missing scope: reload:report`. The fix widened the `access` union in THREE lockstep sites — `types.ts` (`CreateTokenInput.access`), `mappers.ts` (the map), and `CreateTokenDialog.tsx` (the zod enum + the `Select`) — `npx tsc --noEmit` is what proves you caught all three (there is no JS test runner). Two design points to preserve: (1) the **Reloader** option renders only when `type === 'service'` and is reset to `read` on a switch to personal, because `reload:report` is service-token-only (never in an RBAC role map — see `ssm_server/access/scopes.py` and `ssm_server/api/resources/AGENTS.md`), so a personal token could carry it but never *use* it; (2) the Access `Select` had to become controlled (`value={selectedAccess}`) — an uncontrolled `defaultValue` Select can't be programmatically reset on that type switch. RULE: when operators need a new scope from the console, add it as a preset here (or add a real scope-picker) — don't assume the backend grants it by default; it doesn't.
